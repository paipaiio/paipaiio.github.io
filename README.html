02 · 本地预览

当前任务的预览地址是 http://127.0.0.1:1313/。1313 已运行时直接打开并刷新，不要重复启动。写作预览包含草稿 -D；但首页近期文章只展示已发布且有正文的文章。新草稿请在 /posts/ 列表点击或直接访问 /posts/你的-slug/，不是创建失败。修改内容通常实时刷新。配置和布局发生变化后，如有异常，可在启动终端 Ctrl + C 再启动。

新终端会话 · 只在预览服务未运行时执行
cd /Volumes/Pi/blog
PREVIEW_DIR=$(mktemp -d "${TMPDIR:-/tmp}/blog-preview.XXXXXX")
HUGO_RESOURCEDIR="$PREVIEW_DIR/resources" \
  hugo server -D --renderToMemory --noBuildLock --disableFastRender \
  --cacheDir "$PREVIEW_DIR/cache" --port 1313
# 按 Ctrl+C 结束服务后，清理本会话的临时目录：
rm -rf -- "$PREVIEW_DIR"
--renderToMemory 不写 public/；资源与缓存也位于临时目录。服务只在本机运行，端口占用时先确认已有博客服务。不要结束不相关的进程。

临时目录会一直保留到服务结束；最后一行只清理本条命令创建的目录。日常写作使用上面完整命令，正式发布则用“发文章”里的不带 -D 构建。

03 · 文章参数怎么填
文件开头用两个 --- 包住 YAML Front Matter。冒号后有空格，嵌套字段用两个空格缩进。不要混用 +++ TOML 语法与 YAML 键值。
字段建议值 / 作用发布时留意
title文章显示标题，可以中文。标题变更不必改目录名。
slug生成器给出稳定英文 URL 段；模板本身可由目录名决定。发布后尽量不改，旧链接可能失效。
date2026-10-08T14:10:00+08:00填写实际发文时间。未来时间正式构建默认不输出；当前流程不是自动定时发布。
draft写作 true，发布 false。-D 预览可见草稿；正式构建没有 -D。
summary1–2 句列表摘要；留空时 Hugo 按正文生成摘要。内容具体，避免只有空标题。
tags / categoriesYAML 列表，如 ["Hugo", "写作"]。标签用于多维检索，分类用于主题归档；已有同名项复用。
author默认省略，继承站点 MuskZhou。确需不同作者时加 author: "名字"。
cover.image / cover.relative同目录 cover.jpg 与 true，或 image 留空不设封面。文件存在、大小写一致。列表封面是否显示由站点配置控制。
comments新模板 true；省略时继承全站评论配置。本篇设 false 可以关闭，正式站点需正确配置 giscus。
math新模板 false；有公式的文章才设 true。本篇关闭数学，避免价格中的美元符号被当成公式；旧文章仍依其自身/站点参数。

02 · 配置放在哪
TOML 从表标题开始，后续字段都属于这个表，直到下一个表标题。阅读、代码复制、明暗模式都放在 [params]，不是 [params.cover] 里面。把新增字段合并到已有表；一份文件不要重复声明同一表。
要改什么所在层级典型键
网站地址 / 标题 / 主题文件顶层baseURL、title、theme = "PaperMod"
分页[pagination]pagerSize = 10
阅读、代码复制、目录、评论[params]ShowReadingTime、ShowCodeCopyButtons、ShowToc、comments
封面显示[params.cover]hiddenInList、hiddenInSingle、relative（本篇在 Front Matter 填）
首页简介 / 按钮[params.profileMode] 与 [[params.profileMode.buttons]]title、subtitle、imageUrl，按钮的 name / url
顶部菜单 / 社交链接[[menu.main]] / [[params.socialIcons]]name、url、菜单 weight
评论服务[params.giscus]repo、repoId、categoryId
搜索数据[outputs] / [params.fuseOpts]首页输出需保留 "JSON"，搜索页面在 content/search/_index.md。
分类与标签[taxonomies]tag = "tags"、category = "categories"
层级示例 · 合并到对应表
[params]
ShowCodeCopyButtons = true
ShowReadingTime = true
ShowToc = true
defaultTheme = "auto"
comments = true

[params.cover]
hidden = false
hiddenInList = true
hiddenInSingle = false
修改 baseURL 不会替你注册域名或改变 DNS；新值应与实际 Pages 自定义域名一致。首页文案与菜单在项目配置中编辑，头像文件是 static/img/avatar.png。


03 · 评论与扩展功能
评论使用 giscus（GitHub Discussions），当前连接 paipaiio/paipaiio.github.io。更换仓库时，在 giscus 配置页重新选择仓库与分类，再把生成的仓库 / 分类 ID 写入 [params.giscus]。不要只改 repo 而沿用旧 ID。
repoId 与 categoryId 是浏览器使用的公开标识，不是 API 密钥；私人 Token、密码与 API Key 不应写入文章、hugo.toml 或这份 HTML。全站 comments = false 关闭默认评论，本篇 comments: false 只影响这一篇。
数学扩展由 layouts/partials/math.html 渲染，Markdown 源码保留规则在 [markup.goldmark.extensions.passthrough]。Mermaid 来自代码块 hook 与 layouts/partials/mermaid.html。新文章默认数学关闭，公式文章显式开启即可。

测试与独立目录正式构建
不写 public / resources · 不带 -D
cd /Volumes/Pi/blog
./scripts/test.sh

02 · 逐项暂存、提交与推送
先看当前分支与已有改动。仅在确认当前分支是 main，且暂存内容正是此次发布内容后执行提交与推送。工作流目前只有 push: main 触发，没有手动 dispatch 入口。
每次发文 · 换成自己的文章目录
cd /Volumes/Pi/blog
git branch --show-current
git status --short
git diff --stat

# 指定本次文章，连同目录里的配图一起暂存：
git add -- content/posts/my-first-post

# 查看全部已暂存文件和实际差异：
git diff --cached --stat
git diff --cached --check
git diff --cached

# 内容确认完成、当前分支确实是 main 后执行：
git commit -m "docs: publish my first post"
git push origin main
暂存区可能已有别人的 / 以前的改动，git commit 会提交整个暂存区。先逐项核对。若误暂存产物，可用 git restore --staged -- public resources 仅撤出暂存，不删除工作文件。不要把 git add . 当作日常发布捷径。

├── README.html                      # 此使用手册，独立交互 HTML
├── hugo.toml                        # 全站配置
├── archetypes/
│   ├── default.md                   # 非 posts 的默认模板
│   └── posts.md                     # 新文章模板，默认草稿 / math false
├── content/
│   ├── posts/                       # 文章与 Page Bundle 配图
│   ├── about/                       # 关于页
│   ├── archives/                    # 归档
│   ├── search/                      # 搜索页面
│   ├── now/                         # 近期活动
│   └── projects/                    # 小项目页
├── assets/
│   ├── css/extended/custom.css       # 站点级样式
│   └── js/fastsearch.js              # 搜索交互
├── layouts/                         # 项目级模板、渲染 hook 与 partial
├── static/img/avatar.png            # 首页头像
├── themes/PaperMod/                 # Git 子模块，不直接改主题
├── scripts/test.sh                  # 测试入口（Node 内置 test runner）
├── tests/                           # 构建与交互回归测试
├── .github/workflows/hugo.yml        # push main 后构建 / Pages 发布
├── public/                          # 历史生成物；日常流程不写不暂存
└── resources/                       # 生成资源；隔离到临时目录
数据流：content + hugo.toml + assets + layouts + PaperMod → Hugo → 临时 site 目录 → Pages artifact → deploy。技术文档无需挂到 content/posts/，README.html 是仓库使用手册，不会自动变成一篇博客文章。
